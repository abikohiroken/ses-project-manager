# SES案件管理WEBアプリ 画面詳細設計書
## Version 1.0

---

## 1. 画面共通設計

### 1.1 対応端末
- PCを主対象
- タブレット対応
- スマートフォンは閲覧・簡易編集可能
- 案件確認画面はPCでの利用を推奨

### 1.2 基本レイアウト

```text
┌──────────────────────────────────────────────┐
│ ヘッダー: システム名 / 利用者 / ログアウト   │
├──────────┬───────────────────────────────────┤
│ ナビ     │ メインコンテンツ                  │
│          │                                   │
└──────────┴───────────────────────────────────┘
```

ナビ:
- 確認待ち案件
- 正式案件
- CSV取込履歴
- ユーザー管理（ADMINのみ）

### 1.3 共通表示
- 日時: `YYYY/MM/DD HH:mm`
- 月: `YYYY/MM`
- 単価: `60～70万円`
- 空値: `—`
- 必須エラー: フィールド直下に赤字
- 保存成功: 画面上部の一時通知
- API失敗: 操作を維持したままエラー表示
- 二重送信防止: 処理中ボタンをdisabled

### 1.4 権限
VIEWER:
- 入力欄をreadonly
- 更新・状態変更ボタン非表示

OPERATOR:
- 案件確認・編集可能
- ユーザー管理不可

ADMIN:
- 全操作可能

## 2. SCR-001 ログイン

### 2.1 URL

```text
/login
```

### 2.2 項目
- システム名
- 「Googleでログイン」
- 認証エラー
- 利用許可がない場合の案内

### 2.3 処理
1. Google OAuth
2. users.emailを小文字で検索
3. is_active=trueを確認
4. roleをJWTへ設定
5. ログイン後に確認待ち一覧へ遷移

### 2.4 エラー
- 未登録: `このアカウントは利用登録されていません`
- 無効: `このアカウントは無効です`
- OAuth失敗: `ログインに失敗しました`

## 3. SCR-002 確認待ち案件一覧

### 3.1 URL

```text
/project-intakes
```

### 3.2 初期条件
- reviewStatus=PENDING
- receivedAt降順
- pageSize=50

### 3.3 連携状態

画面上部:

```text
Drive接続: 正常
inbox: 2件
最終取込: 2026/08/05 15:01
取込エラー: 1件
```

Drive接続不能の場合:

```text
Drive接続: エラー
最終確認: 2026/08/05 15:30
```

案件一覧自体はDBから表示し、Drive障害でも利用可能とする。

### 3.4 検索条件

| 項目 | UI | 内容 |
|---|---|---|
| キーワード | text | 案件名 |
| 警告 | select | すべて / あり / なし |
| 送信元会社 | text | 部分一致 |
| 開始月 | month | YYYY-MM |
| 受信日From | date | 下限 |
| 受信日To | date | 上限 |
| 表示状態 | select | PENDING等 |

ボタン:
- 検索
- 条件クリア

### 3.5 一覧列

| 列 | 幅目安 | 表示 |
|---|---:|---|
| 警告 | 60 | アイコン・件数 |
| 受付ID | 160 | receptionId |
| 案件名 | 可変 | 空欄時「案件名未設定」 |
| 単価 | 110 | 60～70万円 |
| 開始月 | 90 | 2026/09 |
| 勤務地 | 140 | location |
| 送信元 | 180 | sourceCompany |
| 受信日時 | 140 | receivedAt |
| 操作 | 80 | 確認 |

行クリックまたは確認ボタンでSCR-003。

### 3.6 警告表示
- `PROJECT_NAME_MISSING`: 案件名
- `PRICE_AMBIGUOUS`: 単価
- `START_MONTH_AMBIGUOUS`: 開始時期
- `REQUIRED_SKILLS_MISSING`: 必須スキル
- `MULTIPLE_LOCATIONS`: 勤務地
- `CONFLICTING_INFORMATION`: 条件矛盾
- `PROMPT_INJECTION_SUSPECTED`: 原文内命令

### 3.7 ページング
- 50件
- 前へ / 次へ / ページ番号
- 検索条件をURL Queryへ保持

## 4. SCR-003 案件確認

### 4.1 URL

```text
/project-intakes/{id}
```

### 4.2 レイアウト

PC:

```text
┌────────────────────────────┬────────────────────────────┐
│ 構造化項目・編集            │ LINE原文                   │
│                            │                            │
│ [基本情報]                 │ 送信元 / 受信日時          │
│ [単価・期間]               │ 原文全文                   │
│ [勤務条件]                 │                            │
│ [その他条件]               │ [原文をコピー]             │
└────────────────────────────┴────────────────────────────┘
│ [保存] [正式登録] [既存へ統合] [対象外]                 │
```

スマートフォン:
- 構造化項目
- LINE原文
- 操作ボタン
の順に縦配置。

### 4.3 ヘッダー
- 受付ID
- AI警告バッジ
- 受信日時
- 送信元
- `AI初期値を表示`切替

### 4.4 入力項目

#### 基本情報

| 項目 | UI | 必須 |
|---|---|---:|
| 案件名 | text | 正式登録時○ |
| 案件概要 | textarea | |
| 必須スキル | tag input | |
| 尚可スキル | tag input | |
| ロール | text | |
| 工程 | text | |

#### 単価・期間

| 項目 | UI | 制約 |
|---|---|---|
| 単価下限 | number | 0以上整数 |
| 単価上限 | number | 0以上整数 |
| 精算幅 | text | 100文字 |
| 開始月 | month | YYYY-MM |
| 終了月 | month | 開始月以降 |
| 週稼働日数 | number | 1～7 |

#### 勤務条件

| 項目 | UI |
|---|---|
| 勤務地 | text |
| 最寄駅 | text |
| 勤務形態 | select |
| 勤務形態補足 | textarea |

勤務形態:
- full
- hybrid
- onsite
- unknown

#### その他条件

| 項目 | UI |
|---|---|
| 募集人数 | number |
| 商流 | textarea |
| 面談回数 | number |
| 外国籍可否 | select |
| 年齢条件 | text |
| 国籍条件 | textarea |
| 所属条件 | textarea |

### 4.5 AI初期値
初期値と現在値が異なる項目には`AI値から修正済み`を表示する。

AI初期値を確認できるが、編集できない。

### 4.6 LINE原文
- 改行維持
- 長文スクロール
- HTMLは文字列
- コピー
- URLは`http`と`https`だけリンク化
- 原文は編集不可

### 4.7 保存
- PATCH
- 成功後updatedAt更新
- 画面遷移なし
- 警告コードは自動消去しない
- 保存時に入力制約だけ検証

### 4.8 正式案件として登録
確認ダイアログ:

```text
この内容で正式案件を登録します。
登録後、この確認待ち案件は編集できません。
```

成功:
- 正式案件詳細へ遷移

案件名空欄:
- ボタン実行不可
- 案件名へフォーカス

### 4.9 既存案件へ統合
モーダル:

1. 既存案件検索
2. 対象案件選択
3. 反映する項目へチェック
4. 原文は必ず関連付け
5. 実行確認

初期状態では反映項目をすべて未選択とする。

### 4.10 対象外
確認ダイアログのみ。

成功:
- 一覧の次のPENDING案件へ遷移
- 次がない場合は一覧へ戻る

### 4.11 競合
409時:

```text
この案件は別の操作で更新されています。
最新情報を再読み込みしてください。
```

入力値を保持し、最新データとの再読込を利用者に選択させる。

## 6. SCR-005 正式案件詳細・編集

### 6.1 URL

```text
/projects/{id}
```

### 6.2 構成
タブは作らず、1ページ内に以下を配置する。

1. 案件情報
2. 関連LINE原文
3. 取込元情報

### 6.3 編集
OPERATOR以上:
- `編集`押下で編集モード
- `保存` / `キャンセル`
- projectCodeと状態は通常編集不可

VIEWER:
- 常に閲覧モード

### 6.4 状態操作

| 現在 | ボタン |
|---|---|
| OPEN | 保留 / 募集終了 / アーカイブ |
| ON_HOLD | 再開 / アーカイブ |
| CLOSED | 再募集 / アーカイブ |
| ARCHIVED | なし |

各操作は確認ダイアログを表示する。

### 6.5 関連原文
受信日時降順。

表示:
- 受信日時
- 送信元
- 原文
- intakeの処理種別 REVIEWED / MERGED

## 9. アクセシビリティ・操作

- labelとinputを関連付ける
- 色だけで状態を示さない
- エラーへテキストを表示
- フォーカス表示を消さない
- ダイアログ開始時にフォーカス移動
- ダイアログ終了時に元のボタンへ戻す
- 表の横スクロールを許可
- ボタン文言は動作を明示する

## 10. 画面テスト観点

- VIEWERに編集ボタンが出ない
- 警告あり・なしフィルター
- 原文の改行と特殊文字
- 50,000文字原文
- AI初期値との差分
- 保存競合409
- 正式登録後の再操作禁止
- 統合時の適用項目
- 状態別ボタン
- Drive障害時もDB一覧表示
- スマートフォン縦配置
