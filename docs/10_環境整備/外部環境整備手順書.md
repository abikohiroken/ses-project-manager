## 0. この手順書について

### 0.1 なぜ Phase 5 の前に必要か

Phase 5 は LINE と Google Sheets という**外部サービスが実在しないと検証できない**フェーズである。実装だけ先に進めても、動作確認が一切できず手戻りになる。

特に**公開ドメイン**は以下すべての前提になる。

- LINE Webhook URL（HTTPS必須）
- Google OAuth の承認済みリダイレクトURI
- Dokploy の本番デプロイ

### 0.2 作業の依存関係

上から順に実施する。**順序を入れ替えると詰まる。**

```text
1. 公開ドメインとDNS
       ↓
2. Google Cloud サービスアカウント（Drive/Sheets API有効化を含む）
       ↓
3. Google Drive フォルダ作成 → フォルダID取得
       ↓
4. Googleスプレッドシート作成 → スプレッドシートID取得
       ↓
5. Dokploy 本番デプロイ（環境変数投入）
       ↓
6. Google OAuth に本番リダイレクトURIを追加
       ↓
7. LINE公式アカウント・Messaging APIチャネル作成
       ↓
   （Webhook URLの登録・検証は Phase 5 デプロイ後）
```

### 0.3 目安時間

全体で2〜3時間程度。DNSの伝播待ちが入る場合はさらに時間がかかる。

### 0.4 記録する値

作業しながら以下を控える。すべて §8 の環境変数へ入れる。

| # | 値 | 取得箇所 |
|---:|---|---|
| 1 | 公開ドメイン | §1 |

## 1. 公開ドメインとDNS

### 1.1 決めること

Dokploy上のアプリを公開するホスト名を決める。既存ドメインのサブドメインでよい。

```text
例: ses.<既存ドメイン>
```

### 1.2 DNS設定

DNSの管理画面で、決めたホスト名をVPSのグローバルIPへ向ける。

```text
種別: A
名前: ses
値  : <Xserver VPS のグローバルIP>
TTL : 300（伝播確認しやすいよう短めに）
```

### 1.3 反映確認

```bash
nslookup ses.<既存ドメイン>
```

VPSのIPが返れば完了。反映まで数分〜数時間かかる場合がある。

## 2. Google Cloud サービスアカウント

**注意**: これは Phase 1 で作った OAuth クライアント（利用者ログイン用）とは**別物**である。サービスアカウントはアプリがDrive/Sheetsを読み書きするための機械用アカウント。

### 2.1 プロジェクト

OAuthクライアントを作った `ses-sales-system` プロジェクトをそのまま使う。分けない。

プロジェクトIDを控える → `GOOGLE_PROJECT_ID`

### 2.2 APIの有効化【忘れやすい】

「APIとサービス」→「ライブラリ」から以下2つを有効にする。

```text
Google Drive API
Google Sheets API
```

**これを忘れると、認証は通るのにAPI呼び出しが403で失敗する。** 原因が分かりにくいので必ず先に実施する。

### 2.3 サービスアカウント作成

1. 「IAMと管理」→「サービス アカウント」→「サービス アカウントを作成」
2. 名前: `ses-project-manager`
3. ロールの付与は**不要**（Drive/Sheetsへのアクセスはフォルダ共有で制御するため）
4. 作成完了後、生成されたメールアドレスを控える → `GOOGLE_CLIENT_EMAIL`

```text
例: ses-project-manager@ses-sales-system.iam.gserviceaccount.com
```

### 2.4 秘密鍵の発行

1. 作成したサービスアカウントを開く →「キー」タブ
2. 「鍵を追加」→「新しい鍵を作成」→ **JSON**
3. ダウンロードされたJSONファイルの `private_key` の値を控える → `GOOGLE_PRIVATE_KEY`

JSONの中身は次の形をしている。

```json
{
  "type": "service_account",
  "project_id": "ses-sales-system",
  "client_email": "ses-project-manager@....iam.gserviceaccount.com",
  "private_key": "-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n"
}
```

`private_key` は **`\n` を含む1行の文字列**である。この形のまま環境変数へ入れる。アプリ側が起動時に実改行へ復元する（Phase 4実装済み）。

**このJSONファイルをリポジトリに置かない。** 値を環境変数へ移したら、ファイルは安全な場所へ退避するか削除する。

## 3. Google Drive フォルダ

### 3.1 構成

ルートフォルダ「SES営業システム」は作成済み。

```text
Folder ID: 1TlsmeCDe2PK-S9dWRaRVTtpTq5Pty7IE
```

この配下に3つのフォルダを作る。

```text
SES営業システム/
├─ inbox/       GASが生成した未取込CSV
├─ processed/   取込成功・部分成功・スキップ
└─ error/       ファイル全体エラー
```

`staging` や `processing` は**作らない**。処理中状態はDBで管理する。

### 3.2 フォルダIDの取得

各フォルダを開き、ブラウザのURLから取得する。

```text
https://drive.google.com/drive/folders/【この部分がフォルダID】
```

- inbox → `GOOGLE_DRIVE_INBOX_FOLDER_ID`
- processed → `GOOGLE_DRIVE_PROCESSED_FOLDER_ID`
- error → `GOOGLE_DRIVE_ERROR_FOLDER_ID`

### 3.3 サービスアカウントへ共有

**ルートフォルダ「SES営業システム」**を右クリック →「共有」で、§2.3 のサービスアカウントのメールアドレスを **編集者** として追加する。

配下のinbox/processed/errorは継承されるため、個別の共有は不要。

通知メールの送信は不要（サービスアカウントは受信しない）。

### 3.4 補足

アプリがDriveに対して行うのは**一覧取得・ダウンロード・フォルダ移動**だけである。ファイルの新規作成はGAS側（実行者はスプレッドシートの所有者）が行うため、サービスアカウントの保存容量は問題にならない。

## 4. Googleスプレッドシート

### 4.1 作成

ルートフォルダ「SES営業システム」の直下に作成する。

```text
ファイル名: SES案件取込管理
```

作成後、URLからIDを取得する → `GOOGLE_SHEETS_SPREADSHEET_ID`

```text
https://docs.google.com/spreadsheets/d/【この部分がスプレッドシートID】/edit
```

### 4.2 タイムゾーン設定【重要】

「ファイル」→「設定」→ タイムゾーンを **(GMT+09:00) 東京** にする。

GASのトリガーとタイムスタンプがこの設定に従うため、ここがずれると受信日時が9時間ずれる。

### 4.3 シートの作成

以下4つのシートを作る。シート名は**完全一致**させる。

```text
raw_inbox
structured_projects
export_batches
settings
```

各シートの1行目に、§付録 のヘッダーを貼り付ける。**タブ区切りなので、コピーしてA1セルに貼るだけで各列へ展開される。**

### 4.4 共通設定

各シートで以下を行う。

- 1行目を固定（表示 → 固定 → 1行）
- フィルタを有効化
- 1行目を保護（データ → シートと範囲を保護）

### 4.5 サービスアカウントへ共有

スプレッドシートの「共有」から、§2.3 のサービスアカウントを **編集者** として追加する。

ルートフォルダの共有で継承される場合もあるが、明示的に追加しておくと確実。

### 4.6 settings シートの初期値

`settings` シートには2種類のデータを置く。

**A〜E列: LINE送信元の許可リスト**

2行目以降に、案件を送ってくる相手を登録する。この時点では空でよい（LINE連携後に実際のIDを登録する）。

**H〜I列: システム設定（Key/Value）**

| H列（Key） | I列（Value） |
|---|---|
| `CSV_SCHEMA_VERSION` | `v1` |
| `CSV_INBOX_FOLDER_ID` | §3.2 の inbox フォルダID |
| `CHATGPT_PROMPT_VERSION` | `PROJECT-PARSER-1` |
| `MAX_CHATGPT_ROWS` | `100` |
| `MAX_CSV_ROWS` | `1000` |

**秘密値をこのシートへ書かない。**

## 5. Dokploy 本番デプロイ

Phase 4 までのコードを本番へ出す。Phase 5 を待たずに実施することで、Dockerビルド・マイグレーション・OAuthを先に検証できる。

### 5.1 秘密値の生成

```bash
# AUTH_SECRET
openssl rand -base64 32

# CRON_SECRET
openssl rand -base64 32
```

### 5.2 Dokployの構成

```text
Project: ses-sales-system
├─ Application: ses-project-manager-web
├─ Database:    ses-project-manager-db（PostgreSQL 16）
└─ Schedule Jobs
```

### 5.3 データベース

PostgreSQL 16 を作成し、接続文字列を控える → `DATABASE_URL`

同一Dokployネットワーク内のホスト名を使う。

### 5.4 アプリケーション

- GitHubリポジトリ `abikohiroken/ses-project-manager` を接続
- ブランチ: `main`
- ビルド: Dockerfile
- ポート: 3000
- ドメイン: §1 で決めたホスト名
- **HTTPSを有効化**（Let's Encrypt）。HTTPからHTTPSへリダイレクト

### 5.5 環境変数

§8 の対応表に従って投入する。

`GOOGLE_PRIVATE_KEY` は `\n` を含む1行のまま貼る。改行を実際に入れない。

### 5.6 デプロイと確認

デプロイ後に以下を確認する。

```bash
curl -i https://ses.<既存ドメイン>/api/health
```

`200 {"status":"ok"}` が返ればアプリとDBが正常。

`503` の場合はDB接続かマイグレーションを確認する。

### 5.7 初期ADMINの登録

コンテナ内で seed を実行する。

```bash
npm run db:seed
```

`INITIAL_ADMIN_EMAIL` のアカウントが ADMIN として登録される。

### 5.8 Schedule Job

```text
Name:     drive-import
Cron:     */30 * * * *
Timezone: Asia/Tokyo
Command:  node scripts/drive-import-cron.mjs
```

`drive-move-retry` と `import-reconcile` の個別ジョブは**無効のまま**でよい（通常は取込ジョブ内で実行される）。

## 6. Google OAuth に本番URLを追加

Phase 1 で作った OAuth クライアント `ses-project-manager` を開き、**追加**する（作り直さない）。

**承認済みの JavaScript 生成元**

```text
https://ses.<既存ドメイン>
```

**承認済みのリダイレクト URI**

```text
https://ses.<既存ドメイン>/api/auth/callback/google
```

`http://localhost:3000` の設定は**残したまま**にする。ローカル開発で引き続き使う。

反映に5分〜数時間かかることがある。

本番URLでGoogleログインし、`/project-intakes` へ遷移すれば完了。

## 7. LINE公式アカウント・Messaging APIチャネル

### 7.1 公式アカウント作成

LINE Official Account Manager でアカウントを作成する。無料プランでよい。

### 7.2 Messaging APIチャネル

LINE Developers コンソールで Messaging API チャネルを作成し、以下を控える。

- **チャネルシークレット** → `LINE_CHANNEL_SECRET`
- **チャネルアクセストークン（長期）** → `LINE_CHANNEL_ACCESS_TOKEN`

チャネルアクセストークンは「Messaging API設定」タブで発行する。

### 7.3 応答設定

LINE Official Account Manager の「応答設定」で以下にする。

| 項目 | 設定 |
|---|---|
| 応答メッセージ | オフ |
| あいさつメッセージ | 任意 |
| Webhook | **オン** |

自動応答が有効だとWebhookと競合する。

### 7.4 グループ参加の許可

案件がグループで送られてくる場合、「グループ・複数人トークへの参加を許可する」を**オン**にする。

### 7.5 Webhook URLの登録は Phase 5 完了後

```text
https://ses.<既存ドメイン>/api/webhooks/line
```

**この登録と「検証」ボタンは、Phase 5 をデプロイした後に行う。**

Phase 5 未実装の時点では `/api/webhooks/line` が存在しないため、検証は必ず失敗する。今の段階ではチャネルの作成とシークレット・トークンの取得までにとどめる。

## 付録: スプレッドシート貼り付け用ヘッダー

各シートの **A1セル** に貼り付ける。タブ区切りなので自動で列に展開される。

### raw_inbox（13列 A〜M）

```text
reception_id	line_message_id	line_user_id	line_group_id	source_company	source_contact	is_allowed	received_at	message_type	raw_text	status	structured_at	error_message
```

### structured_projects（37列 A〜AK）

CSV33列（A〜AG）+ 管理列4つ（AH〜AK）。

```text
reception_id	line_message_id	line_user_id	line_group_id	project_name	project_summary	required_skills	preferred_skills	role	process	unit_price_min_man	unit_price_max_man	settlement_range	start_month	end_month	work_days_per_week	location	nearest_station	remote_style	remote_note	recruitment_count	commercial_flow	interview_count	foreigner_allowed	age_limit	nationality_note	employment_condition	source_company	source_contact	received_at	raw_text	warning_codes	prompt_version	export_status	batch_id	exported_at	structure_error
```

**A〜AG の33列は CSV のヘッダーと完全一致していなければならない。** 順序も含めて一致しないと取込がヘッダー不一致で失敗する。手入力せず必ずコピーで貼ること。

### export_batches（9列 A〜I）

```text
batch_id	schema_version	prompt_version	target_count	file_name	drive_file_id	status	generated_at	error_message
```

### settings（A〜E列）

```text
line_user_id	line_group_id	source_company	source_contact	is_allowed
```

H1セルに以下を貼る（Key/Value）。

```text
key	value
```

H2以降は §4.6 の表を手入力する。
