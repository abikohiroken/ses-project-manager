作成日時: 2026-08-07 15:40 +09:00

Phase 5（LINE Webhook・Google Sheets連携）を実際に動かすために必要な外部環境の構築手順。

## 0. この手順書の使い方

### 0.1 前提

- Phase 1〜6 の実装は完了済み（PR #1〜#6 マージ済み）
- Google OAuth クライアント（利用者ログイン用）は Phase 1 で作成済み
- Google Drive のルートフォルダ「SES営業システム」は作成済み

### 0.2 画面の文言が違ったら

各サービスのUIは更新されることがある。**手順書の文言と実際の画面が違う場合は、その画面のスクリーンショットを送ってください。** 手順書を修正します。推測で進めて設定を間違えるより早いです。

### 0.3 作業の依存関係

上から順に行う。順序を入れ替えると詰まる。

```text
§1 ドメインとDNS
     ↓
§2 Google Cloud サービスアカウント
     ↓
§3 Google Drive フォルダ
     ↓
§4 Googleスプレッドシート
     ↓
§5 Dokploy 本番デプロイ
     ↓
§6 OAuth に本番URLを追加
     ↓
§7 LINE公式アカウント
     ↓
§8 環境変数の一覧 / §9 完了チェック
     ↓
§11 後続作業（接続と通し確認）
```

§1〜§7 は「箱を用意する」作業、§11 は「作ったものを繋いで動かす」作業。§9 が全部埋まるまで §11 へ進まない。

## §1. ドメインとDNS

### 1-1. VPSのグローバルIPを確認する

Xserver VPS の管理パネルにログインし、対象サーバーの **IPアドレス** を確認する。

```text
[1] 公開ドメイン = ses.<既存ドメイン>
    VPSのIP     = xxx.xxx.xxx.xxx
```

### 1-2. DNSにAレコードを追加する

ドメインを管理しているサービス（Xserverドメイン、お名前.com、Cloudflare など）のDNS設定画面を開く。

**「DNSレコード設定」「DNSレコード追加」** といった名前のメニューにある。

追加する内容:

| 項目 | 入力する値 |
|---|---|
| ホスト名 / 名前 / サブドメイン | `ses` |
| 種別 / タイプ | `A` |
| 内容 / 値 / IPアドレス | VPSのグローバルIP |
| TTL | `300`（選べる場合。伝播確認をしやすくするため短めに） |

**「追加する」「確認画面へ進む」** ボタンを押して確定する。

> ホスト名の欄に `ses.example.jp` のようにフルで入れる方式のサービスもあります。その画面で既存レコードがどう表示されているかに合わせてください。

### 1-3. 反映を確認する

コマンドプロンプトまたはPowerShellで実行する。

```bash
nslookup ses.<既存ドメイン>
```

VPSのIPが返れば完了。まだの場合は数分〜数時間待つ。

## §2. Google Cloud サービスアカウント

**注意**: Phase 1 で作った OAuth クライアント（利用者ログイン用）とは**別物**です。サービスアカウントは、アプリがDriveとスプレッドシートを読み書きするための機械用アカウントです。

### 2-1. プロジェクトを選ぶ

1. https://console.cloud.google.com を開く
2. 画面上部のプロジェクト選択（`ses-sales-system` と表示されている部分）をクリック
3. `ses-sales-system` が選ばれていることを確認する

**Phase 1 と同じプロジェクトを使う。** 新規に作らない。

プロジェクトIDを控える。プロジェクト選択のダイアログに「ID」列がある。

```text
[2] GOOGLE_PROJECT_ID = ses-sales-system（実際に表示されているID）
```

### 2-2. APIを2つ有効にする【忘れると必ず失敗する】

**これを飛ばすと、認証は通るのにAPI呼び出しだけ403で失敗します。** 原因が分かりにくいので必ず先にやってください。

1. 左上のハンバーガーメニュー（≡）→ **「APIとサービス」** → **「ライブラリ」**
2. 検索欄に `Google Drive API` と入力
3. 検索結果の **「Google Drive API」** をクリック
4. **「有効にする」** ボタンを押す
5. 「ライブラリ」へ戻り、検索欄に `Google Sheets API` と入力
6. **「Google Sheets API」** をクリック
7. **「有効にする」** ボタンを押す

#### 確認方法

「APIとサービス」→ **「有効なAPIとサービス」** を開き、一覧に次の2つがあること。

```text
Google Drive API
Google Sheets API
```

### 2-3. サービスアカウントを作成する

1. ハンバーガーメニュー → **「IAMと管理」** → **「サービス アカウント」**
2. 画面上部の **「＋ サービス アカウントを作成」** をクリック

3段階のフォームが出る。

**ステップ1「サービス アカウントの詳細」**

| 項目 | 入力する値 |
|---|---|
| サービス アカウント名 | `ses-project-manager` |
| サービス アカウント ID | 自動で入る（そのままでよい） |
| 説明 | `SES案件管理アプリのDrive/Sheets接続用`（任意） |

**「作成して続行」** を押す。

**ステップ2「このサービス アカウントにプロジェクトへのアクセスを許可する」**

**何も選ばずに「続行」** を押す。

> ロールは付けません。DriveとスプレッドシートへのアクセスはGoogle Drive側の「共有」で制御するため、プロジェクトのIAMロールは不要です。

**ステップ3「ユーザーにこのサービス アカウントへのアクセスを許可」**

**何も入力せずに「完了」** を押す。

### 2-4. サービスアカウントのメールアドレスを控える

サービスアカウント一覧に戻ると、作成したものが表示される。**「メール」** 列の値を控える。

```text
[3] GOOGLE_CLIENT_EMAIL = ses-project-manager@ses-sales-system.iam.gserviceaccount.com
```

このアドレスは §3 と §4 の共有設定で使う。

### 2-5. 秘密鍵（JSON）を発行する

1. 一覧で作成したサービスアカウントの**メールアドレスをクリック**して詳細を開く
2. 上部のタブから **「キー」** を選ぶ
3. **「鍵を追加」** → **「新しい鍵を作成」**
4. キーのタイプで **「JSON」** を選択（既定で選ばれている）
5. **「作成」** を押す

JSONファイルが自動的にダウンロードされる。ファイル名は `ses-sales-system-xxxxxxxx.json` のような形。

### 2-6. JSONから秘密鍵を取り出す

ダウンロードしたJSONをメモ帳などのテキストエディタで開く。次のような中身になっている。

```json
{
  "type": "service_account",
  "project_id": "ses-sales-system",
  "private_key_id": "...",
  "private_key": "-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBg...(長い)...\n-----END PRIVATE KEY-----\n",
  "client_email": "ses-project-manager@ses-sales-system.iam.gserviceaccount.com",
  ...
}
```

`private_key` の値（**ダブルクォートの内側だけ**）をコピーして控える。

```text
[4] GOOGLE_PRIVATE_KEY = -----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBg...\n-----END PRIVATE KEY-----\n
```

**重要な注意**

- `\n` は**そのままの文字として**残す。改行に置き換えない。アプリが起動時に実改行へ復元する（Phase 4実装済み）
- 前後のダブルクォートは含めない
- **このJSONファイルをリポジトリに置かない。** 値を控えたら、パスワード管理ソフトなど安全な場所へ移すか削除する

## §3. Google Drive フォルダ

### 3-1. ルートフォルダを開く

https://drive.google.com/drive/folders/1TlsmeCDe2PK-S9dWRaRVTtpTq5Pty7IE

「SES営業システム」フォルダが開く。

### 3-2. 3つのフォルダを作る

このフォルダの中で、以下を3回繰り返す。

1. 画面左上の **「＋ 新規」** をクリック（または画面の空白部分を右クリック）
2. **「新しいフォルダ」** を選ぶ
3. 名前を入力して **「作成」**

作る名前（**すべて小文字・半角**）:

```text
inbox
processed
error
```

完成した構成:

```text
SES営業システム/
├─ inbox/
├─ processed/
└─ error/
```

> `staging` や `processing` は作りません。処理中の状態はデータベース側で管理します。

### 3-3. 各フォルダのIDを取得する

フォルダを**ダブルクリックして開く**と、ブラウザのアドレスバーが次のようになる。

```text
https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz012345
                                       ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                       この部分がフォルダID
```

3つとも開いて控える。

```text
[5] GOOGLE_DRIVE_INBOX_FOLDER_ID     =
[6] GOOGLE_DRIVE_PROCESSED_FOLDER_ID =
[7] GOOGLE_DRIVE_ERROR_FOLDER_ID     =
```

**取り違えに注意。** inbox と processed を逆に設定すると、取込済みファイルを取り込もうとして動作がおかしくなります。

### 3-4. サービスアカウントへ共有する

**ルートフォルダ「SES営業システム」**に対して行う。配下の3フォルダは継承されるので個別の設定は不要。

1. 「SES営業システム」フォルダを**右クリック**
2. **「共有」** → **「共有」**
3. 「ユーザーやグループを追加」欄に §2-4 で控えたサービスアカウントのメールアドレスを貼り付ける
4. 右側の権限プルダウンを **「編集者」** にする
5. **「通知を送信」のチェックを外す**（サービスアカウントはメールを受信しません）
6. **「共有」** ボタンを押す

#### 確認方法

もう一度「共有」を開き、サービスアカウントが **編集者** として一覧に出ていること。

## §4. Googleスプレッドシート

### 4-1. スプレッドシートを作る

1. Drive の「SES営業システム」フォルダを開く
2. **「＋ 新規」** → **「Google スプレッドシート」** → **「空白のスプレッドシート」**
3. 左上の「無題のスプレッドシート」をクリックして、名前を **`SES案件取込管理`** に変更

### 4-2. スプレッドシートIDを控える

アドレスバーから取得する。

```text
https://docs.google.com/spreadsheets/d/1XyZaBcDeFgHiJkLmNoPqRsTuVwX23456/edit
                                       ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                       この部分がスプレッドシートID
```

```text
[8] GOOGLE_SHEETS_SPREADSHEET_ID =
```

### 4-3. タイムゾーンを東京にする【必須】

**ここがずれると受信日時が9時間ずれます。**

1. メニューの **「ファイル」** → **「設定」**
2. **「全般」** タブの **「タイムゾーン」** を **`(GMT+09:00) 東京`** に変更
3. **「設定を保存」** を押す

### 4-4. シートを4つ作る

画面下部のシートタブで操作する。

**1枚目（既存の「シート1」）の名前を変える**

1. 下部の **「シート1」** タブを**ダブルクリック**（または右クリック →「名前を変更」）
2. `raw_inbox` と入力して Enter

**残り3枚を追加する**

下部左の **「＋」** をクリック → 新しいシートができる → タブをダブルクリックして名前を変更。これを3回。

```text
structured_projects
export_batches
settings
```

最終的にタブが左から次の並びになる（並び順は動作に影響しないが揃えておくと分かりやすい）。

```text
raw_inbox | structured_projects | export_batches | settings
```

**シート名は完全一致させること。** 半角・小文字・アンダースコア。

### 4-5. 各シートにヘッダーを貼り付ける

**§付録A** のヘッダーをコピーして、各シートの **A1セル** に貼り付ける。

タブ区切りなので、A1に貼るだけで各列へ自動で展開される。

| シート | 列数 | 最終列 |
|---|---:|---|
| `raw_inbox` | 13 | M |
| `structured_projects` | 37 | AK |
| `export_batches` | 9 | I |
| `settings` | 5（A〜E） | E |

**手入力しないこと。** 特に `structured_projects` のA〜AG（33列）はCSVのヘッダーと**1文字でも違うと取込が全件失敗**します。必ずコピーで貼ってください。

#### 貼り付け手順

1. 付録のコードブロックの中身を選択してコピー
2. 対象シートの **A1セル をクリック**
3. `Ctrl+V` で貼り付け

貼った直後に「貼り付け方法」のポップアップが出た場合は、既定のまま（テキストを列に分割）でよい。

### 4-6. 各シートの共通設定

4つのシートすべてで行う。

**1行目を固定**

1. 1行目のどこかのセルを選択
2. メニューの **「表示」** → **「固定」** → **「1行」**

**フィルタを有効化**

1. 1行目を選択
2. メニューの **「データ」** → **「フィルタを作成」**

**1行目を保護（誤編集の防止）**

1. 1行目を選択して右クリック
2. **「セルでの他の操作項目を表示」** → **「範囲を保護」**
3. 右側のパネルで **「権限を設定」** → **「この範囲を編集できるユーザーを制限する」** → 自分のみ
4. **「完了」**

> 保護は必須ではありませんが、ヘッダーを誤って書き換えると取込が全件失敗するため推奨します。

### 4-7. settings シートに初期値を入れる

`settings` シートには2種類のデータを置く。

**A〜E列: LINE送信元の許可リスト**

2行目以降は**この時点では空のまま**にする。実際のLINE IDは §11-A で分かってから登録する。

**H〜I列: システム設定（Key/Value）**

H1セルに以下を貼り付ける（タブ区切り）。

```text
key	value
```

H2以降に手入力する。

| セル | 入力する値 | セル | 入力する値 |
|---|---|---|---|
| H2 | `CSV_SCHEMA_VERSION` | I2 | `v1` |
| H3 | `CSV_INBOX_FOLDER_ID` | I3 | §3-3 の **inbox** フォルダID |
| H4 | `CHATGPT_PROMPT_VERSION` | I4 | `PROJECT-PARSER-1` |
| H5 | `MAX_CHATGPT_ROWS` | I5 | `100` |
| H6 | `MAX_CSV_ROWS` | I6 | `1000` |

> H3 に入れるのは **inbox** のフォルダIDです。processed や error ではありません。

**秘密値をこのシートに書かないこと。**

### 4-8. サービスアカウントへ共有する

1. スプレッドシート右上の **「共有」** ボタンをクリック
2. §2-4 のサービスアカウントのメールアドレスを入力
3. 権限を **「編集者」** にする
4. **「通知を送信」のチェックを外す**
5. **「共有」** を押す

> ルートフォルダの共有から継承される場合もありますが、明示的に追加しておくと確実です。

## §5. Dokploy 本番デプロイ

Phase 6 までのコードを本番へ出す。LINE連携より前にやることで、Dockerビルド・マイグレーション・Googleログインを先に検証できる。

### 5-1. 秘密値を2つ生成する

Git Bash またはWSLで実行する。

```bash
openssl rand -base64 32
```

2回実行して、それぞれ控える。

```text
[10] AUTH_SECRET  = （1回目の出力）
[11] CRON_SECRET  = （2回目の出力）
```

> PowerShellしかない場合:
> `[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Max 256 }))`

### 5-2. プロジェクトを作る

1. Dokploy にログイン
2. 左メニューの **「Projects」** → **「Create Project」**
3. Name に `ses-sales-system` を入力
4. **「Create」**

### 5-3. PostgreSQL を作る

1. 作成したプロジェクトを開く
2. **「Create Service」** → **「Database」** → **「Postgres」**
3. 入力する。

| 項目 | 入力する値 |
|---|---|
| Name | `ses-project-manager-db` |
| Database Name | `ses_project_manager` |
| Database User | `ses_app` |
| Database Password | 強いパスワードを生成して入力（控える） |
| Docker Image | `postgres:16`（選択できる場合） |

4. **「Create」**
5. 作成後、サービスを開いて **「Deploy」** を押す

#### 接続文字列を組み立てる

Dokploy の同一ネットワーク内ではサービス名でアクセスできる。データベースの詳細画面に **Internal Connection URL** が表示されるので、それを使うのが確実。

表示がない場合は次の形で組み立てる。

```text
postgresql://ses_app:<パスワード>@ses-project-manager-db:5432/ses_project_manager
```

```text
[9] DATABASE_URL =
```

> パスワードに `@` `:` `/` などの記号が含まれるとURLが壊れます。英数字のみのパスワードにするか、URLエンコードしてください。

### 5-4. アプリケーションを作る

1. プロジェクト画面で **「Create Service」** → **「Application」**
2. Name に `ses-project-manager-web` を入力
3. **「Create」**

### 5-5. GitHubリポジトリを接続する

作成したアプリケーションを開き、**「General」** タブで設定する。

1. **Provider** で **「GitHub」** を選択
   - 初回は GitHub App の連携が必要。**「Configure GitHub App」** 等の案内に従って `abikohiroken` アカウントへインストールし、`ses-project-manager` リポジトリへのアクセスを許可する
2. **Repository** で `abikohiroken/ses-project-manager` を選択
3. **Branch** で `main` を選択
4. **Build Type** で **「Dockerfile」** を選択
5. Dockerfile 用の3項目を入力する。

| 項目 | 入力する値 |
|---|---|
| Dockerfile Path (Required) | `Dockerfile` |
| Docker Context Path | `.` |
| Docker Build Stage | （空欄のまま） |

6. **「Save」**

### 5-6. 環境変数を入れる

**「Environment」** タブを開き、§8 の一覧をすべて入力する。

Dokploy の環境変数欄は `KEY=value` 形式を1行ずつ書く方式。§8.3 のブロックをそのまま貼り付けて、右辺を埋めるのが早い。

**`GOOGLE_PRIVATE_KEY` の入れ方**

```text
GOOGLE_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBg...\n-----END PRIVATE KEY-----\n
```

- `\n` は**文字として**そのまま入れる。実際の改行キーを押さない
- 値をダブルクォートで囲まない
- 途中で改行しない（1行に収める）

入力後 **「Save」** を押す。

### 5-7. ドメインとHTTPSを設定する

**「Domains」** タブを開き、**「Add Domain」** を押す。

| 項目 | 入力する値 |
|---|---|
| Host | `ses.<既存ドメイン>` |
| Path | `/` |
| Container Port | `3000` |
| HTTPS | **オン** |
| Certificate | **`letsencrypt`** |

**「Create」** または **「Save」** を押す。

> Let's Encrypt の証明書発行には §1 のDNSが反映済みであることが必要です。反映前だと失敗します。

### 5-8. デプロイする

1. アプリケーション画面右上の **「Deploy」** を押す
2. **「Deployments」** タブでログを見る
3. ビルドとマイグレーションが通り、コンテナが起動することを確認する

#### 確認方法

```bash

```

期待する結果:

```text

{"status":"ok"}
```

| 結果 | 原因 |
|---|---|
| `503 {"status":"unavailable"}` | DB接続不可。`DATABASE_URL` を確認 |

| 502 / 応答なし | コンテナ起動失敗。Deployments のログでマイグレーションエラーを確認 |

4. **「Create」**

> Dokploy の Application Job は `docker exec` でアプリコンテナ内でコマンドを実行します。**対象コンテナが起動していないと実行に失敗する**ため、§5-8 が成功してから登録してください。

### A. LINE Webhook の接続

#### A-1. Webhook URL を登録する

1. https://developers.line.biz/console/ でチャネルを開く
2. **「Messaging API設定」** タブを開く
3. **「Webhook設定」** の **「Webhook URL」** 欄の **「編集」** を押す
4. 次を入力して **「更新」**

```text
https://ses.<既存ドメイン>/api/webhooks/line
```

5. **「検証」** ボタンを押す

**「成功」** と表示されれば接続できている。

#### A-2. 失敗した場合の切り分け

| 表示 | 原因 | 対処 |
|---|---|---|
| 404 | Phase 5 がデプロイされていない | Dokployで `main` の最新をデプロイ |
| 401 | `LINE_CHANNEL_SECRET` の値が違う | §7-3 の値とDokployの環境変数を照合 |
| 503 | `GOOGLE_SHEETS_SPREADSHEET_ID` 未設定 / Sheets API無効 | §2-2・§4-2 を確認 |
| タイムアウト | HTTPSが有効でない | §5-7 の Certificate を確認 |

#### A-3. Webhookの利用をオンにする

同じ **「Messaging API設定」** タブの **「Webhookの利用」** を **オン** にする。

**登録しただけでは配信されません。** このトグルが必要です。

#### A-4. 最初のメッセージは必ず無視される【正常な挙動】

LINEでテストメッセージを1件送る。

`raw_inbox` シートを見ると、行は追加されるが次の状態になっている。

```text
G列 is_allowed = FALSE
K列 status     = IGNORED
```

**これは不具合ではありません。** `settings` の許可リストが空だからです。未許可の送信元でも原文は保存し、ChatGPTの処理対象から外すのが設計です。

#### A-5. 送信元を許可リストへ登録する

A-4 で追加された `raw_inbox` の行から値を読み取る。

| raw_inbox の列 | 内容 |
|---|---|
| C列 `line_user_id` | 送信者のユーザーID（`U` で始まる長い文字列） |
| D列 `line_group_id` | グループID（グループから送られた場合のみ。`C` で始まる） |

これを `settings` シートの2行目以降へ登録する。

| settings の列 | 入力する値 |
|---|---|
| A列 `line_user_id` | 個人からの送信を許可するなら raw_inbox のC列の値 |
| B列 `line_group_id` | グループを許可するなら raw_inbox のD列の値 |
| C列 `source_company` | 相手の会社名 |
| D列 `source_contact` | 担当者名 |
| E列 `is_allowed` | `TRUE` |

**グループ運用の場合はB列だけ埋めれば十分です。** 判定はグループIDが優先されます。

#### A-6. 再送して確認する

もう一度LINEへメッセージを送り、`raw_inbox` の新しい行が次になることを確認する。

```text
G列 is_allowed      = TRUE
K列 status          = UNPROCESSED
E列 source_company  = settings から転記されている
F列 source_contact  = settings から転記されている
```

ここまでで **LINE → スプレッドシート** が通る。

### B. GAS の配置と単体確認

詳細は **[`gas/README.md`](../../gas/README.md)** を参照。

#### B-1. Apps Script エディタを開く

1. スプレッドシート `SES案件取込管理` を開く
2. メニューの **「拡張機能」** → **「Apps Script」**

新しいタブでエディタが開く。

#### B-2. ファイルを7つ作る

既定で `コード.gs` が1つある。これを `Code.gs` にリネームし、残り6つを追加する。

**ファイルの追加方法**

左メニューの **「ファイル」** の横の **「＋」** → **「スクリプト」** → 名前を入力

**作る順序**（依存関係の都合でこの順が安全）

```text

2. BatchService.gs
3. Config.gs

5. DriveService.gs

7. Code.gs（既存のコード.gsをリネーム）
```

> Apps Script はファイル名に `.gs` を自動で付けます。名前入力欄には `CsvWriter` のように拡張子なしで入れてください。

各ファイルに、リポジトリの `gas/` 配下の同名ファイルの中身を**全文コピーして貼り付ける**。

貼り付けたら **Ctrl+S**（またはフロッピーアイコン）で保存。

#### B-3. タイムゾーンを設定する

1. 左メニューの **歯車アイコン（プロジェクトの設定）** をクリック
2. **「タイムゾーン」** を **`(GMT+09:00) 日本標準時 - 東京`** に設定

#### B-4. settings のGAS用キーを確認する

`gas/README.md` はGASが使う3つを挙げているが、§4-7 で5つとも設定済みのはず。読む側が違うだけで、**5つとも必要**。

| キー | 読む側 |
|---|---|
| `CSV_SCHEMA_VERSION` | GAS |
| `CSV_INBOX_FOLDER_ID` | GAS |
| `MAX_CSV_ROWS` | GAS |
| `CHATGPT_PROMPT_VERSION` | ChatGPT |
| `MAX_CHATGPT_ROWS` | ChatGPT |

#### B-5. 手動実行して権限を承認する

1. エディタ上部の関数選択プルダウンで **`exportWaitingProjectsToCsv`** を選ぶ
2. **「実行」** を押す
3. 「承認が必要です」ダイアログが出る → **「権限を確認」**
4. Googleアカウントを選ぶ
5. 「このアプリは確認されていません」と出たら **「詳細」** → **「（プロジェクト名）に移動」**
6. **「許可」** を押す

初回はこの承認が必要。`structured_projects` が空なら「対象0件」で正常終了する。

#### B-6. 手動テストを実施する

**[`docs/11_手動テスト/GAS手動テスト手順書.md`](../11_手動テスト/GAS手動テスト手順書.md)** の §2（12項目）を実施する。

`structured_projects` へ手で行を入れて確認するため、**ChatGPTが動いていなくても実施できる。**

特に重要な4項目:

| # | 内容 | 落ちると何が起きるか |
|---|---|---|
| 2.5 | UTF-8で9MiB超相当 | 日本語のバイト長計算を誤ると10MiB超のCSVができ、取込が全件拒否 |
| 2.7 | 同時実行 | Script Lockが効かないと同じ案件が複数バッチに入る |
| 2.9 | CSV保存後のシート更新失敗 | CSVを再作成すると重複ファイルが生まれる |
| 2.11 | 特殊文字を含む原文 | セル内改行・カンマ・引用符でCSVが壊れると全件失敗 |

#### B-7. Phase 4 との結合確認【最重要】

手順書 §3 を実施する。GASが作ったCSVを実際に取込へ流す。

```text
1. GASでCSVを生成（Drive inbox にファイルができる）
2. Dokploy の Schedules で「drive-import」を手動実行
3. アプリの「CSV取込履歴」画面で status=SUCCESS を確認
4. 「確認待ち案件一覧」に案件が現れる
5. Drive の processed へファイルが移動している
```

**ここが通れば、CSVの33列とファイル名がアプリ側と一致していることが実証されます。** ヘッダー1文字の差でも失敗するため、最も重要な結合点です。

失敗した場合は「CSV取込履歴」の詳細で `errorCode` を確認する。

| errorCode | 意味 |
|---|---|
| `HEADER_MISMATCH` | ヘッダーの名称か順序が違う |
| `INVALID_FILE_NAME` | ファイル名の形式が違う |
| `INVALID_UTF8_BOM` | BOMが付いていない |
| `FILE_TOO_LARGE` | 10MiB超（バイト長計算の誤り） |

#### B-8. トリガーを設定する

**B-6 と B-7 が通ってから**行う。

1. Apps Script エディタの左メニューの **時計アイコン（トリガー）**
2. 右下の **「トリガーを追加」**
3. 設定する。

| 項目 | 選ぶ値 |
|---|---|
| 実行する関数を選択 | `exportWaitingProjectsToCsv` |
| 実行するデプロイを選択 | `Head` |
| イベントのソースを選択 | **時間主導型** |
| 時間ベースのトリガーのタイプを選択 | **分ベースのタイマー** |

## 付録B. 状態値の早見表

シートを見るときの参考。

### raw_inbox の status

| 値 | 意味 |
|---|---|
| `UNPROCESSED` | ChatGPT処理待ち |
| `STRUCTURED` | 構造化済み |
| `ERROR` | 構造化に失敗 |
| `IGNORED` | 未許可の送信元。処理対象外 |

### structured_projects の export_status

| 値 | 意味 |
|---|---|
| `WAITING` | CSV出力待ち |
| `RESERVED` | バッチに予約済み（処理中） |
| `EXPORTED` | CSV出力済み |
| `ERROR` | 出力に失敗 |

### CSV取込履歴の status

| 値 | 意味 |
|---|---|
| `SUCCESS` | 全行登録成功 |
| `PARTIAL_SUCCESS` | 一部の行がエラー。正常行は登録済み |
| `SKIPPED` | 重複のためスキップ（`FILE_DUPLICATE` / `ALL_ROWS_SKIPPED`） |
| `ERROR` | ファイル全体が処理できず |
| `PROCESSING` | 処理中 |
