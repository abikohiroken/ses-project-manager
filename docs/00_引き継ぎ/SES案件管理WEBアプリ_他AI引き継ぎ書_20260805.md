# SES案件管理WEBアプリ 他AI引き継ぎ書
## 2026-08-05版

---

## 1. プロジェクト概要

LINE公式アカウントで受信したSES案件情報を、Googleスプレッドシート・ChatGPT・Google Apps Script・Google Drive・WEBアプリを経由して案件DBへ登録するシステムを開発する。

目的は、LINEで届く非構造化案件情報を自動で構造化し、人間が原文と比較・修正した後に正式案件として登録できるようにすること。

---

## 2. 確定した全体フロー

```text
案件送信者
  ↓
LINE公式アカウント
  ↓ Webhook
Next.js /api/webhooks/line
  ↓ x-line-signature検証
Google Sheets API
  ↓
Googleスプレッドシート raw_inbox
  ↓
ChatGPTスケジュール機能
  ↓
Googleスプレッドシート structured_projects
  ↓
Google Apps Scriptが30分ごとにCSV生成
  ↓
Google Drive / inbox
  ↓
Dokploy上のWEBアプリが30分ごとに確認
  ↓
CSV検証・重複確認
  ↓
project_intakesへ確認待ち登録
  ↓
人間がLINE原文と構造化値を比較・修正
  ├─ 新規正式案件 → projects
  ├─ 既存案件へ統合
  └─ 対象外
  ↓
CSVをprocessedまたはerrorへ移動
```

---

## 3. 重要な設計判断

### 3.1 LINE Webhook受信
当初はGoogle Apps ScriptでLINE Webhookを直接受信する案だったが、署名検証の都合により変更済み。

確定構成:

```text
LINE → Next.jsで署名検証 → Google Sheets API → raw_inbox
```

Next.js側で未加工のリクエスト本文と`x-line-signature`を使用して署名検証する。

### 3.2 未確認案件と正式案件の分離
AI構造化結果は直接正式案件へ登録しない。

```text
project_intakes
  ↓ 人間確認
projects
```

### 3.3 原文
LINE原文は変更不可。

正本:

```text
project_sources.raw_text
```

`projects`へ原文を重複保存しない。

### 3.4 AI初期値
AI構造化結果は以下へ固定保存する。

```text
project_intakes.ai_snapshot
```

人間が編集する値は`project_intakes`の通常カラムへ保存する。

### 3.5 スキル
初期版ではスキルマスタを作らない。

```text
required_skills: JSON string[]
preferred_skills: JSON string[]
```

### 3.6 Drive構成

```text
SES営業システム/
├─ inbox/
├─ processed/
├─ error/
└─ SES案件取込管理スプレッドシート
```

`staging`と`processing`フォルダは作らない。

処理中状態はDBで管理する。

## 8. CSV確定仕様

### 8.1 基本
- UTF-8 BOM付き
- CRLF
- 全セルをダブルクォート
- 1案件1行
- 最大1,000行
- 最大10MiB
- GAS生成目標9MiB以下
- 33列固定

### 8.2 列


### 8.3 ファイル名

```text
ses_projects_v1_BATCH-YYYYMMDD-HHMMSS-XXXXXX.csv
```

### 8.4 取込
- `drive_file_id`で同一ファイル二重処理防止
- `file_hash`で同一内容をSKIPPED
- 一部行エラーでも正常行は登録
- DB登録成功後のDrive移動失敗は`MOVE_PENDING`
- 次回はDB登録せず移動だけ再試行

## 12. ChatGPTスケジュール

### 12.1 実行

### 12.2 対象

```text
raw_inbox.status = UNPROCESSED
raw_inbox.is_allowed = TRUE
```

### 12.3 重要ルール
- 原文を信頼しない

- 原文にない値を作らない
- 不明は空欄またはunknown
- 1入力1出力
- 複数案件へ自動分割しない
- prompt_version=`PROJECT-PARSER-1`

## 19. 実装時の禁止事項

- LINE原文を編集可能にしない
- AI構造化結果を直接正式案件にしない
- `projects`へraw_textを重複保存しない
- 独自CSV split実装をしない
- `dangerouslySetInnerHTML`を使わない
- VIEWERの更新を画面非表示だけで済ませない
- updatedAt競合確認を省略しない
- DB登録成功後のDrive移動失敗で再登録しない
- GitHubへ秘密鍵・APIキーを保存しない
- 本番で`prisma db push`を使わない
- migrationなしでDBを変更しない
- GASでLINE Webhookを直接受信する構成へ戻さない

## 20. 最終目標

利用者はLINEで届いた案件について、WEBアプリ上で以下を行える。

1. 確認待ち案件を開く
2. LINE原文を確認する
3. AI構造化値を修正する
4. 正式案件として登録する
5. 既存案件へ統合する
6. 対象外にする
7. 正式案件を検索・編集する
8. CSV取込エラーを確認する

人員管理・案件マッチング・提案・面談・契約は将来拡張であり、初期実装に含めない。
